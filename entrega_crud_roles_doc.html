1. Arquitectura Técnica: Control de Acceso Basado en Roles (RBAC) Doble Capa Cliente + Servidor

La seguridad en arquitecturas modernas Serverless no recae exclusivamente en el frontend. Se implementa un modelo de defensa en profundidad: en el cliente, Angular Signals y control de flujo declarativo (@if) adaptan la experiencia de usuario ocultando controles no autorizados; en el servidor, Políticas de Seguridad a Nivel de Fila (RLS) de PostgreSQL garantizan que cualquier petición directa a Supabase sea rechazada criptográficamente si no posee privilegios de administrador.

2. Configuración Backend (SQL & RLS) PostgreSQL Supabase
-- 1. Enumeración de roles y tabla profiles CREATE TYPE public.user_role AS ENUM ('admin', 'user'); CREATE TABLE public.profiles ( id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY, role public.user_role DEFAULT 'user' NOT NULL ); -- 2. Tabla de clientes con UUID autogenerado CREATE TABLE public.clients ( id UUID DEFAULT gen_random_uuid() PRIMARY KEY, nombre TEXT NOT NULL, empresa TEXT NOT NULL, email TEXT NOT NULL UNIQUE, created_at TIMESTAMPTZ DEFAULT NOW() ); -- 3. Habilitar RLS estricto en ambas tablas ALTER TABLE public.clients ENABLE ROW LEVEL SECURITY; ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; -- 4. Políticas RLS: Lectura autenticada, Escritura SOLO Admins CREATE POLICY "Lectura para autenticados" ON public.clients FOR SELECT TO authenticated USING (true); CREATE POLICY "Escritura solo para admins" ON public.clients FOR ALL TO authenticated USING (EXISTS (SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'admin')) WITH CHECK (EXISTS (SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'admin'));

3. Servicio Reactivo de Supabase (src/app/services/supabase.service.ts) Angular Signals + SupabaseClient
@Injectable({ providedIn: 'root' }) export class SupabaseService { private supabase: SupabaseClient = createClient(environment.supabaseUrl, environment.supabaseKey); // Señales reactivas para propagación instantánea del estado global public currentUser = signal<User | null>(null); public userRole = signal<'admin' | 'user' | null>('admin'); async getClients(): Promise<Client[]> { const { data, error } = await this.supabase.from('clients').select('*').order('created_at', { ascending: false }); if (error) throw error; return data || []; } async createClient(client: Client): Promise<void> { const { error } = await this.supabase.from('clients').insert([client]); if (error) throw error; } async updateClient(id: string, client: Partial<Client>): Promise<void> { const { error } = await this.supabase.from('clients').update(client).eq('id', id); if (error) throw error; } async deleteClient(id: string): Promise<void> { const { error } = await this.supabase.from('clients').delete().eq('id', id); if (error) throw error; } }

7. Conclusiones y Cumplimiento de Resultados de Aprendizaje Evaluación DAM2
Reactividad Signals: La eliminación de NgModule y el uso de signal<T> permite una propagación instantánea del rol sin recargar la página ni provocar memory leaks.
Seguridad Servidor (RLS): Las políticas de PostgreSQL impiden cualquier ataque por bypass de cliente o inyección desde la consola DevTools, garantizando integridad ACID.
UX Móvil Nativa: El componente ion-item-sliding junto a los eventos táctiles proporcionan una experiencia indistinguible de una app móvil nativa en Android/iOS.
